# S23 Ultra 실기 검증 기록

검증일: 2026-10-13 (한국 시간). Samsung SM-S918N, Android API 36. 무선 ADB로 설치한 debug 앱이며 기존 모델·레시피 데이터는 유지했다. AWS 인프라 생성·배포는 이번 변경에서 실행하지 않았다.

## 확인한 항목

- 공식 범용 Gemma 4 E2B 파일 2,588,147,712 bytes를 사용자 승인 후 앱에서 다운로드했다. 활성화 전 고정 SHA-256을 확인했다. 파일은 앱의 백업 제외 전용 디렉터리에 저장되어 있다.
- LiteRT-LM의 실제 GPU 초기화와 한국어 JSON 답변 생성이 기기에서 실행됐다. 서버 모델을 호출한 결과가 아니다.
- 실제 테스트 레시피 `https://www.10000recipe.com/recipe/6850292`를 원문 사이트에서 가져와 사진·13개 재료·16단계를 표시했다. 원문 `2 servings`가 2인분으로 표시되고 처음 목표 인분도 2다.
- 터치 다음 버튼으로 원문 1단계에서 2단계로 이동했다. 이동은 완료가 아니다.
- `LocalPersistenceTest`: 실제 AtomicFile 저장소에서 초점·건너뛰기·대기 타이머·명령 ID의 복원을 확인했다.
- `LocalConcurrentTurnTest`: 모델 응답을 보류한 상태에서 수동 이동이 완료되고, 오래된 완료 제안이 최신 초점을 덮지 않는지 확인했다.
- 기기의 on-device STT 서비스가 `ko-KR` 설치를 보고했다. TTS는 설치된 네트워크 불필요 한국어 음성 5개를 보고했다. **실제 발화 인식·재생 정확도와 장시간 주방 소음은 시험하지 않았다.** 이 메타데이터 확인은 녹음·재생·추가 다운로드 없이 수행했다.

## 로컬 모델의 품질과 속도

자가 작성한 3단계 평가 레시피로 ‘손질 사진’, ‘없는 재료 대체’, ‘2인분의 물’ 질문을 시험했다. 이는 실제 테스트 레시피 전체 요리나 모든 요리 상황 검증이 아니다.

| 실행 | 관찰 | 판정 |
| --- | --- | --- |
| 1차 | GPU 로딩 14.37초, 첫 답변 11.82초. 손질 답변은 생성했지만 질문을 UNCERTAIN으로 잘못 분류 | 사진·발화 분류 실패 |
| 2차 | 로딩 6.39초, 답변 약 12.7~15.8초. 손질 답변에 끓이기 단계 번호를 선택했고 물 질문을 재료 변경으로 오해 | 품질 실패 |
| 3차 | 로딩 7.38초, 답변 12.59/18.95/12.46초. 원문 손질 설명은 답했지만 사진을 생략했고 목표 인분을 원문 인분과 혼동 | 품질 실패; 안전하지 않은 상태 변경은 검증기로 차단 |

3차 앱 프로세스 최고 RSS는 약 1.13 GiB (`VmHWM=1,188,844 KiB`)였다. GPU 메모리 총량이나 모든 환경의 메모리 요구량으로 해석하면 안 된다. 실행마다 캐시·배터리·온도·문맥이 달라 이 수치를 제품 성능 보장으로 사용할 수 없다.

**실행 가능성은 확인됐지만, 로컬 AI를 출시 품질이라고 판단하지 않는다.** 실패 기준을 낮추지 않고 원문 근거 매핑·원문/목표 분량 구분을 수정해 재검증한다. 잘못된 완료·대체·타이머 제안은 실제 사실로 저장하거나 실행하지 않는다. 모델의 자연어 조언 자체가 항상 정확하다는 보장은 없다.

## 자동 검사

이번 UI 재설계 이전 baseline: Android 단위 테스트 62개(실패/오류 0), debug APK·AndroidTest APK·lintDebug 성공. 서버 테스트 65개(실패/오류 0). 실기 instrumentation 5개 중 상태 저장·동시 처리 2개는 통과, 음성 지원 메타데이터 2개는 확인, 실제 Gemma 품질 1개는 위 이유로 실패했다. 최신 UI 재설계 후 결과는 아래에 별도로 갱신한다.

## 최신 밝은 UI 재설계 검증

- 최종 PC 빌드에서 `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `lintDebug`가 성공했다. 단위 테스트는 66개이며 실패/오류 0이다. lint 성공은 경고가 없다는 의미가 아니다.
- 무선 디버깅 주소 `<device-address>`로 밝은 UI APK를 기존 데이터 유지 방식으로 설치했다. 재료 체크/준비 개수/재료별 ‘없어요’ 선택을 제거한 것을 화면과 소스에서 확인했다.
- 실제 레시피 상세에서 음식 사진·출처·원문 2인분을 확인했다. 목표 2→1인분 변경 때 재료량이 ‘비례 참고’와 원문량을 함께 표시하고, 다시 2인분으로 되돌리는 것을 확인했다. 조리 순서 탭 전환도 확인했다.
- `screenshots/hansul-preview.png`는 새 크림/테라코타 상세 화면의 실제 S23 Ultra 캡처다. 다른 기존 화면 캡처는 이전 디자인일 수 있어 최신 조리 화면의 근거로 사용하지 않는다.
- 사용자가 휴대폰 사용 중이라고 알려 추가 설치·화면 조작·AI 실기 테스트를 중단했다. 이후 마지막 단계 CTA, 질문 입력 접근성 라벨, 음성 켜짐 설명, 진행 칩 줄바꿈과 실험 기능 안내를 보강한 최종 APK는 PC에만 생성되어 있다. 이 보강본을 휴대폰에 재설치하지 않았다.
- 4차 모델 보강은 원문/목표 인분을 구조화하고, 고유한 답변 근거로 사진을 찾고, 무관한 타이머 제안을 제거한다. 새 회귀 테스트는 통과했으나 **4차 실제 모델 평가를 실행하지 않았으며**, 3차 품질 실패를 해결했다고 판단하지 않는다.

## 남은 실기 검증

- 최종 보강 APK 설치, 새 조리 화면·질문 바·사진 확대·수동 스크롤 초점·마지막 단계 CTA. 밝은 상세 화면·재료/순서 탭은 위 범위에서 확인했다.
- 4차 실제 Gemma 손질 사진·누락 재료 상담·원문/목표 인분 구별 평가.
- 자연스러운 생략·다른 사람에게 한 말·소음·오래 듣기·한국어 음성 전사 품질.
- 실제 요리의 대체재·안전/알레르기·부분 행동·인분 변경의 정량 판단.
- 실제 알람 수신, 권한 철회, 제조사 절전, 재부팅 뒤 복원. 알람의 절대 마감 재등록 코드는 구현했지만 휴대폰을 재부팅하지 않았다. Android 강제 종료 중에는 앱을 다시 열기 전 OS 제한이 있다.
- 외부 원문 사진이 없거나 설명과 다르면 정확한 손질 이미지를 보장할 수 없다. 외부 앱 참고 화면·로고·사진을 한술 자산으로 복사하지 않는다.

## 영상 레시피 가져오기 (2026-11-05)

**휴대폰·에뮬레이터에서 실행하지 않았다.** PC 자동 검사만 수행했다. 서버 테스트 610개, Android 단위 테스트 162개 모두 실패/오류 0이며 debug APK 빌드가 성공했다. 실제 Gemini·YouTube API도 호출하지 않았다. 설명은 [영상 레시피 가져오기](VIDEO_RECIPE_IMPORT.md)에 있다.

실기에서 확인할 항목:

- YouTube 앱·브라우저·갤러리의 `공유 → 한술`, 영상 분석 전 로그인 요구, 휴대폰 영상 동의 화면.
- 휴대폰 영상 복사·압축(Media3)·조각 업로드·중단 뒤 이어 올리기·단계 장면 추출.
- YouTube 임베드 재생과 Referer 허용, 임베드 불가 영상의 바깥 앱 열기, 백그라운드 전환·화면 꺼짐·마이크 켜기 때 재생 멈춤.
- 서버에 Gemini 키를 설정한 뒤 실제 한국어 요리 영상의 받아쓰기·레시피 품질, 분석 시간과 비용.
